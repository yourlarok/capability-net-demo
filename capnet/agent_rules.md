
# capnet：先找别人走通的路，再动手；做完留下反馈

capnet 的路由对所有人完整开放，**是否上报不影响任何路由结果**。

## 1. 何时调用路由

- 用户提出多步骤、有行业惯例的任务（"改进营销视频""做一套网课""起号""直播复盘"）→ 调 `plan_task`。
  - 自己判断任务类型并传 `task_type`：产出类 `produce` / 改进类 `improve` / 增长类 `grow` / 发布类 `launch` / 复盘类 `review`；
    问答、排障、买什么、法规咨询传 `qa`（不走工作流，直接回答）。
  - 知道目标市场就传 `market`（国内平台 `cn`，海外 `global`）。
- 只缺一个具体能力（"找个能转字幕的工具"）→ 调 `find_capability`。
- **两个工具都要传 `capability_type`**：你自己判断需求属于哪类能力（image 图像 / video 视频 / speech 语音配音 /
  music 音乐 / sound 音效与音频处理 / text 文字 / data 数据调研 / marketing 营销投放 / commerce 电商 /
  publish 发布 / game 游戏 / 3d / code 开发，可多选）。例："给角色配个萌妹声音"→`["speech"]`，
  "画角色立绘"→`["image"]`，"给视频配乐"→`["music"]`。不传时只能靠关键词猜，换个说法就可能猜错。
- 未命中工作流时：按常识自行拆解执行，**不要编造工具**；缺口已自动记录。

## 2. 如何使用返回的计划

- 返回的是排版好的 Markdown（能力卡、对比表、阶段清单），**原样展示给用户**，不要改写成纯文字摘要。

- 按阶段推进，每阶段对照"交付物"和"验收/指标"自检，不达标不进下一阶段。
- 工具标注 `agent 可调用` 的可以直接用；标注 `人工使用`（gui/manual）的**只能推荐给用户操作**，绝不假装调用。
- 每张卡都带「接入渠道」。API 工具调用前先检查卡上写的环境变量是否已设置；没设置就把「申请凭证」链接和变量名告诉用户，请用户自己设好环境变量，**不要让用户把 Key 贴进对话**。人工工具按卡上的网页版 / 下载 / 找人渠道指引用户。
- 计划里"开工前需要你提供"的项目，缺什么就先向用户要什么，别凭空假设数据。

## 3. 任务结束时：记录隐式反馈（每次都做，不打扰用户）

capnet 是一个能力社区：系统维护的**基石 flow** 是底座，用户在使用中走出来的路会长成**社区 flow**。
它靠每次任务结束时的一条反馈生长：工具与 flow 的评分、新 flow 的注册都来自这里。

**开工前（只问一次）**：如果 `plan_task` 提示用户还没选上报方式，用一句话问：
"任务结束后，匿名的解决思路要「自动上报 / 每次先确认 / 不上报」？不上报不影响任何功能。"
按回答调 `set_share_mode`（auto / ask / off）。之后不要再问。

**任务结束时**（用户接受了结果、只用了一部分、或者放弃/转去别处），调 `finish_task`。
字段全部来自你对这次对话的观察，**不要为了填它去问用户**：

| 字段 | 怎么判断 | 不要写 |
|---|---|---|
| `outcome` | 用户采用了结果 → `accepted`；只用了一部分 → `partial`；放弃、换方案、不了了之 → `abandoned` | — |
| `corrections` | 用户纠正你、表示不满、要求重来的次数（"不对""不是这个意思""重来""太差了"） | — |
| `skipped` | 计划里你们没有做的阶段名 | — |
| `workflow_id` | 依据的 flow（`plan_task` 返回的 `workflow_id`）；没有现成 flow 就留空——你走出的这条路会成为社区 flow 的候选 | — |
| `problem` | 泛化的问题类型："营销视频完播率低" | 公司名、产品名、品牌、人名 |
| `steps[].stage/domain` | 实际做过的阶段与能力领域 | — |
| `steps[].entry_id` | 用户最终选用的工具 id（`plan_task` 返回的 `id`） | 内部/私有工具名（留空即可） |
| `steps[].ok/retries` | 是否成功、返工了几次 | — |
| `steps[].approach` | **方法**，一句话："用留存曲线定位 3 秒跌点，再对齐画面找原因" | 具体文案、脚本、数据数值、文件路径、链接、金额 |
| `lessons` | 可迁移的经验："卖点要在 5 秒内出现" | 只对该客户成立的结论 |

`finish_task` 会先做规则清理（联系方式、证件、密钥、路径、链接、金额、作品名、姓+称谓、私有词表），然后：

- **auto**：自动上报清理后的思路，告诉用户一句"已匿名记录本次思路"即可。
- **ask**：返回预览。**把预览原样展示给用户**，有 ⚠ 的逐条指出，问是否同意上报：
  同意 → `submit_trace(preview_id, consent=true)`；拒绝 → `submit_trace(preview_id, consent=false)`；
  想改 → 按要求改，重新 `finish_task`。不要反复劝说，一次任务最多问一次。
- **off**：只在本机生效（本机的评分和"你上次这样做过"照常可用），不上报。

连接的是**远程 capnet 服务**时，服务端收到即算上报：记住用户开工前的选择，每次在 `finish_task` 里传 `share_mode`；
用户没选或选了不上报，就传 `off`，或者干脆不调用。

`summarize_trace` 是旧接口：只生成预览、不记录反馈，仅在用户主动要求"把这次思路整理出来给我看"时使用。

## 4. 私有词表

用户可以在 `~/.capnet/private_terms.txt`（每行一个词）里列出公司名、产品名、客户名、人名，
汇总时会被自动替换为 `[私有]`。用户提到"别把 XX 传出去"时，建议他把 XX 加进去。
