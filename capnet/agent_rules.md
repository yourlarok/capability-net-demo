
# capnet：先找成熟做法，再动手；做完可选择回馈思路

capnet 的路由对所有人完整开放，**是否上传轨迹不影响任何路由结果**。

## 1. 何时调用路由

- 用户提出多步骤、有行业惯例的任务（"改进营销视频""做一套网课""起号""直播复盘"）→ 调 `plan_task`。
  - 自己判断任务类型并传 `task_type`：产出类 `produce` / 改进类 `improve` / 增长类 `grow` / 发布类 `launch` / 复盘类 `review`；
    问答、排障、买什么、法规咨询传 `qa`（不走工作流，直接回答）。
  - 知道目标市场就传 `market`（国内平台 `cn`，海外 `global`）。
- 只缺一个具体能力（"找个能转字幕的工具"）→ 调 `find_capability`。
- 未命中工作流时：按常识自行拆解执行，**不要编造工具**；缺口已自动记录。

## 2. 如何使用返回的计划

- 按阶段推进，每阶段对照"交付物"和"验收/指标"自检，不达标不进下一阶段。
- 工具标注 `agent 可调用` 的可以直接用；标注 `人工使用`（gui/manual）的**只能推荐给用户操作**，绝不假装调用。
- 计划里"开工前需要你提供"的项目，缺什么就先向用户要什么，别凭空假设数据。

## 3. 任务完成后：汇总思路（可选，必须征得同意）

只有在任务确实走完（用户接受或明确放弃）后才做。整理一份执行记录调用 `summarize_trace`：

| 字段 | 写什么 | 不要写 |
|---|---|---|
| `problem` | 泛化的问题类型："营销视频播放量低" | 公司名、产品名、品牌、人名 |
| `steps[].stage/domain` | 阶段名与能力领域 | — |
| `steps[].entry_id` | 用到的注册表工具 id（plan_task 返回的 `id`） | 内部/私有工具名（留空即可） |
| `steps[].ok/retries` | 是否成功、返工了几次 | — |
| `steps[].approach` | **方法**，一句话："用留存曲线定位 3 秒跌点，再对齐画面找原因" | 具体文案、脚本内容、数据数值、文件路径、链接、金额 |
| `lessons` | 可迁移的经验："卖点要在 5 秒内出现" | 只对该客户成立的结论 |
| `accepted` | 用户是否接受了结果 | — |

`summarize_trace` 会再做一遍规则清理（联系方式、证件、密钥、路径、链接、金额、作品名、姓+称谓、用户私有词表），
并返回预览和 `preview_id`。此时：

1. **把预览原样展示给用户**，不要删改、不要只给摘要；有 ⚠ 提示的逐条指给用户看。
2. **问用户是否同意上传**（有选择题工具就用选择题："同意上传 / 不上传 / 我先改一下"）。说明清楚：
   上传的只有上面这些思路；不上传不影响任何功能。
3. 用户同意 → `submit_trace(preview_id, consent=true)`。
   用户拒绝 → `submit_trace(preview_id, consent=false)`（删除本地预览）。
   用户想改 → 按要求改执行记录，重新 `summarize_trace`，再次确认。
4. 永远不要在用户没有明确同意时上传；不要反复劝说；一次任务最多问一次。

## 4. 私有词表

用户可以在 `~/.capnet/private_terms.txt`（每行一个词）里列出公司名、产品名、客户名、人名，
汇总时会被自动替换为 `[私有]`。用户提到"别把 XX 传出去"时，建议他把 XX 加进去。
