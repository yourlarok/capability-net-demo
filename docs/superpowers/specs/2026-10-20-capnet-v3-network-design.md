# capnet v3：从注册表到"经验网络"

日期：2026-10-20
状态：草案（待用户确认）

## 一句话定位

**agent 的 Waze**：每个接入的 agent 在完成任务时顺手产生"哪条路走通了"的轨迹，
网络把轨迹提炼成可复用的工作流与工具口碑，再回流给所有接入者。
卖的不是工具清单（谁都能爬），是**带结果统计的、被验证过的做事方法**。

## 对 v2 思路的关键修正

| v2 隐含假设 | 修正 |
|---|---|
| 价值单位是"工具卡" | 工具是商品；价值单位是 **(任务类型, 工作流, 工具) 三元组上的结果数据** |
| 别人会来"贡献工作流" | 几乎没人会写工作流。贡献必须是**使用的副产品**：上报轨迹 = 零额外动作 |
| 打分公式是核心 | 公式是可复制的标准件；**结果信号的获取与可信度**才是核心 |
| 通用全领域 | 先赢一个垂直：AI 内容生产（短剧/MV/游戏资产），你本人就是第一重度用户 |

## 对象模型：三层 + 一条轨迹

```
Capability  原子能力（app#domain），可自动调用 or 人工使用
   ▲ 填充
Workflow    阶段 DAG，阶段的工具抽象为带契约的槽位（输入输出类型 + 不变量 + 验收谓词）
   ▲ 归纳 / 强化
Trace       一次真实执行：有序步骤[(stage, domain, entry, ok, retries, cost)] + 是否被接受
```

- Trace 是唯一原始数据。卡的 Q/R/C 和工作流的支持度**都从 Trace 派生**，不再各自维护。
- 同一条 Trace 两用：`credit()` 拆成逐条目遥测；`induce()` 聚类成工作流草稿（已实现，`capnet/traces.py`）。

## 设计原则

1. **贡献 = 副产品，但必须征得同意。** 任务结束时 agent 按 capnet skill 汇总思路，原样展示预览，
   用户同意才上传（用户决策 2026-10-20）。隐式信号优先于显式评分：重试次数、被替换、返工、放弃，比五星评分诚实得多。
2. **只传客观思路，不传内容。** 轨迹 = 问题类型 + 步骤(领域/工具/成败/重试/方法一句话) + 经验；
   任务原文、产出、成本金额、精确时间一律不传，贡献者只是随机安装 id 的哈希。
3. **支持度按独立贡献者计。** 一个人刷 1 万次也只算 1（已实现）。后续叠加贡献者信誉权重、
   厂商自荐检测（某卡的好评过度集中在少数账号 → 降权）。
4. **槽位是类型签名。** 换工具 = 类型检查：输出类型匹配 + 不变量（如 `character_lock`）可满足 +
   验收谓词可执行。工作流因此像程序一样可组合、可验证，而不是一段说明文字。
5. **两级同一套打分。** 工具在槽位内竞争，工作流在任务类型内竞争，复用 Wilson/贝叶斯/UCB；
   上下文化（按行业/用户画像）走 contextual bandit，而不是全局一个榜。
6. **工作流像 git 一样有谱系。** 归纳出的变体是 fork，同构轨迹强化原工作流（`reinforces`），
   每个工作流可追溯到支持它的轨迹集合。
7. **协议先于平台。** 对外暴露为一个 MCP server，任何 agent（Claude Code / Cursor / 自研）即插即用：
   `plan_task` · `find_capability` · `list_workflows` · `get_workflow` · `summarize_trace` · `submit_trace`（已实现）。
   分发渠道 = MCP 生态本身。
8. **路由对所有人完整开放，上传完全自愿（用户决策 2026-10-20，取代早先的 give-to-get 设想）。**
   网络靠"好用"吸引接入，靠低摩擦、可信的隐私处理让一部分用户愿意回馈；不以降级逼迫上传。

## 飞轮

```
接入者的 agent 调 plan_task → 按工作流执行 → summarize_trace 预览 → 用户同意 → submit_trace
   → credit() 更新工具口碑  → induce() 产出/强化工作流  → gaps 记录答不出的任务
   → 下一位接入者拿到更准的路由（冷启动更短）→ 更多人接入
```

## 护城河与风险（诚实版）

- **护城河**：跨厂商的结果数据。单个工具厂商只看得到自己的工具；模型厂商有调用数据但不中立，
  也覆盖不到 gui/manual 能力（剪映、Aseprite、调色师）。
- **最大风险**：平台原生化（模型厂商自带 tool search / skill 市场）。应对：中立 + 垂直深度 +
  人工能力覆盖 + 工作流契约，这些是通用平台不愿做的脏活。
- **冷启动风险**：没有轨迹就没有一切。对策：先用自己的生产（opapyon / 短剧 / 游戏）当唯一数据源跑通，
  轨迹 ≥ 几百条、归纳出的工作流确实被复用后，再开放接入。

## 路线

- **P0（本次已做）**：Trace 模型 + credit + induce + 脱敏 + 支持度防刷；修复 v1 http 卡误标"人工使用"。
- **P1（已做）**：规划器、行业工作流、业务目录、三套批量评测。
- **P2（已做）**：MCP server（6 工具）、capnet skill、隐私清理、两段式同意上传、hub（HTTP/本地）、
  轨迹事件回流打分、归纳草稿 + `promote` 评审入库、市场上下文。
- **P2.5**：槽位契约 + 换卡类型检查；英文/跨语言召回（embedding）。
- **P3**：位置去偏的 C（或改用 Q/R 为主）、按领域的 UCB 与探索预算、种子统计带时间戳参与衰减。
- **P4**：多接入者：贡献者信誉权重、厂商自荐检测、多 hub 联邦同步。

## 批量评测结论（2026-10-20，实现后）

72 题三套：dev 36（调参用）/ holdout 20（看过一次后修了任务类型门）/ blind 16（写完只跑一次，未调参）。

| 集 | 命中@1 | 域外拒识 | 槽位覆盖 | 自动化率 |
|---|---|---|---|---|
| dev | 97% | 100% | 100% | 48% |
| holdout | 100% | 100% | 100% | 46% |
| blind | 90% | 100% | 100% | 49% |

评测中发现并修复的问题：
1. **未见词被静默丢弃**：查询主题词（"装修""马拉松"）不在语料里就不计入分母，泛词撑起虚高相关度 → `field_relevance(unseen_idf=…)` + 实义证据门。
2. **词面只认话题、不认任务类型**：holdout 对抗题"电脑播放视频卡顿""播客耳机推荐"全部误入工作流（拒识 0%）→ 任务类型门。生产中应由调用方 agent 传 `task_type`，词表只是兜底。
3. **alt_domains 平权竞争**：小说写作工具顶掉营销文案工具 → 主 domain 优先、alt 只补位；同一 app 去重。

仍未解决（下一步）：
- 词面检索不跨语言：英文营销题匹配度 0.03 未命中 → embedding 召回或多语 intents。
- 任务类型门的召回代价："没什么反响，帮我看看问题在哪"无线索词被拒 → 交给 LLM 传 TaskSpec。
- **无市场/地域上下文**：中国公司的抖音场景，A/B 槽仍列出 Meta Ads（冷启动流行度先验主导）→ 卡加 `markets`、画像加市场，作为上下文乘子。
- **营销槽位自动化率只有 ~45%**：国内数据/投放平台几乎全是封闭 GUI。这本身是机会：给这些平台做 MCP/浏览器自动化适配器，是网络里价值密度最高的补位。
- dev/holdout 的 intents 与题目同一作者，数字偏乐观；blind 90% 更接近真实，需要真实用户的提问日志来校准。

## 上传与隐私（P2 实现）

```
agent 整理执行记录 ──summarize_trace──▶ 本地清理 + 预览 + 指纹(preview_id)，存 ~/.capnet/pending/
                                         │ 原样展示给用户（含"已清理"清单与 ⚠ 残留风险提示）
              用户拒绝 ◀─────────────────┤
   submit(consent=false) 删除预览         │ 用户同意
                                         ▼
                        submit(preview_id, consent=true)
                        └ 重新计算指纹，与 preview_id 不符（被改过）→ 拒绝
                        └ CAPNET_HUB_URL 有值 → POST /v1/traces；否则写本机 hub
hub.ingest：服务端再清理一遍（不信任客户端）→ 指纹去重 → traces.jsonl + events.jsonl
Registry.load 读 events.jsonl → 上传的轨迹直接影响路由打分
hub refresh → induce → data/workflows_drafts/ → 人工评审 → promote 入正式库
```

清理规则（`capnet/privacy.py`）：密钥、邮箱、链接、证件号、卡号、手机/座机、IP、路径、@账号、金额、《作品名》、
常见姓氏+称谓、用户私有词表（`~/.capnet/private_terms.txt`）；注册表外的工具名置空；文本限长；时间截到天。
规则不能识别任意人名/机构名，因此"原样展示 + 明确同意"是不可省略的第二道防线；残留风险以 ⚠ 提示给用户。

## 接入层：与客户端无关（v0.4）

核心只有 `Server`（6 个工具）+ `agent_rules.md`（唯一的使用规范）。外壳：

| 外壳 | 模块 | 覆盖 |
|---|---|---|
| stdio MCP | `mcp_server.main` | 所有本地 MCP 客户端；`clients.py` 为 8 种客户端生成/合并配置 |
| Streamable HTTP MCP | `http_api` `POST /mcp` | 填 URL 的平台（Claude.ai 连接器、Dify、Coze…） |
| REST + OpenAPI 3.1 | `http_api` `/v1/tools/*`、`/openapi.json` | GPTs Actions、插件市场、工作流引擎 |
| function calling 导出 / 库 | `clients.export_tools`、`Server.call` | 自研 agent、SDK 循环 |

规范分发：Claude skill 正文 == `agent_rules.md`（测试保证一致）；MCP `prompts/get capnet_rules`；`GET /v1/rules`；OpenAPI description。
关键约束（人工工具不可假装调用、上传须同意）同时写进工具描述，因为不是每个客户端都会把 `instructions` 交给模型。

远程模式的取舍：执行记录在服务端内存里清理（不落盘、不记日志），弱于本地清理；贡献者 = hash(X-Capnet-Client | MCP 会话 id)，
会话可被刷，女巫问题与"贡献者信誉"一起列在未解决清单。
