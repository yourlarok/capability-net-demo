# capnet 使用教程

capnet 是一个"能力与工作流路由网络"：agent 遇到多步骤的专业任务时，先向它要一份**成熟工作流 + 每一步该用什么工具**的计划；任务做完后，可以在用户同意的前提下，把清理过的"客观解决思路"回传，帮网络归纳新工作流、校准工具排名。

- 路由对所有人完整开放，**上不上传轨迹都不影响任何结果**。
- 零第三方依赖，只要 Python 3.11+。

---

## 0. 一句话安装（推荐）

对你正在用的 agent 说：

> 请阅读 https://raw.githubusercontent.com/yourlarok/capability-net-demo/v3-traces/INSTALL.md ，按里面的说明帮我安装 capnet。

这份说明是写给 agent 看的（[INSTALL.md](../INSTALL.md)），agent 会自己做完这几步：

1. **安装**：`uv tool install "capnet @ <GitHub 源码包地址>"`，没有 uv 就用 `pip install --user`。直接下载源码包，不需要 git，也不克隆仓库。
2. **接入**：运行 `capnet setup`。它会探测本机的 Claude Code、Codex、Gemini CLI、Cursor、Windsurf、Claude Desktop，写入 MCP 配置，再把使用规范装到各自的位置（Claude Code 是 skill，Codex 和 Gemini 是全局说明文件里带标记的区块）。只改 capnet 自己的那一项，改之前先备份为 `.bak`；重复执行只会更新，不会重复添加。
3. **报告**：把改动清单给你看，并提醒你重启客户端。

撤销：`capnet setup --remove`；更新：重新执行第 1 步。

下面第 1 节是手动接入和其他接入方式（远程服务、OpenAPI、function calling），给需要定制的人看。

---

## 1. 接入：任何 agent 都能用

capnet 不绑定任何一家 agent。核心是同一组 8 个工具和一份使用规范，外面套了四种接入方式：

| 方式 | 适合谁 | 需要本地装代码吗 |
|---|---|---|
| **A. 本地 MCP（stdio）** | Claude Code、Codex CLI、Gemini CLI、Cursor、Windsurf、VS Code Copilot、Cline、Claude Desktop、Cherry Studio 等所有支持 MCP 的客户端 | 要 |
| **B. 远程 MCP（HTTP）** | 同上，再加上只能填 URL 的平台：Claude.ai 自定义连接器、Dify、Coze 等 | 不用，有人起一台服务即可 |
| **C. REST + OpenAPI** | 不支持 MCP 的平台：GPTs Actions、Coze/Dify 自定义插件、n8n、各种工作流引擎 | 不用 |
| **D. Function calling / Python 库** | 自研 agent、LangChain/LlamaIndex，或直接调用 OpenAI/Anthropic/Gemini SDK | 看情况 |

不管用哪种方式，**都要把使用规范交给 agent**（第 1.6 节）。规范里写明了"人工工具不能假装调用"和"上传必须先征得同意"。

下文用 `<CAPNET>` 指仓库所在路径，例如 `D:/capability-net-demo`。

### 1.1 获取代码（A、D 需要；B、C 只有服务端需要）

```bash
git clone -b v3-traces https://github.com/yourlarok/capability-net-demo.git
cd capability-net-demo
python demo.py plan "抖音视频完播率低，怎么改"     # 能输出计划就说明可用（Python 3.11+，零依赖）
```

### 1.2 方式 A：本地 MCP，一条命令生成配置

```bash
python demo.py config list                 # 查看支持的客户端
python demo.py config cursor               # 打印配置片段和配置文件位置
python demo.py config cursor --write       # 直接合并进配置文件（先备份为 .bak，只改 capnet 这一项）
```

| 客户端 | 命令 | 写到哪里 |
|---|---|---|
| Claude Code | `python demo.py config claude-code`，然后执行它打印出来的 `claude mcp add ...` | CLI 管理 |
| Codex CLI | `python demo.py config codex --write` | `~/.codex/config.toml` |
| Gemini CLI | `python demo.py config gemini-cli --write` | `~/.gemini/settings.json` |
| Cursor | `python demo.py config cursor --write` | `~/.cursor/mcp.json` |
| Windsurf | `python demo.py config windsurf --write` | `~/.codeium/windsurf/mcp_config.json` |
| VS Code (Copilot) | 在项目目录执行 `python demo.py config vscode --write` | `.vscode/mcp.json` |
| Claude Desktop | `python demo.py config claude-desktop --write` | `%APPDATA%\Claude\claude_desktop_config.json`（mac 为 `~/Library/Application Support/Claude/`） |
| Cline / 其他 | `python demo.py config cline`，把片段粘进它的 MCP 设置 | 客户端 MCP 面板 |

生成的配置会用当前 Python 的绝对路径和 `demo.py` 的绝对路径，所以在哪个项目里都能用。改完配置后重启客户端。

要把轨迹汇总到别人的 hub，加上 `--env CAPNET_HUB_URL=http://<hub地址>:8765`。

### 1.3 方式 B：远程 MCP（不用本地安装）

在一台机器上起服务：

```bash
python demo.py serve --host 0.0.0.0 --port 8765
# 想加访问口令：先设环境变量 CAPNET_API_KEY=<口令>，客户端带 Authorization: Bearer <口令>
# 对外地址与监听地址不同（反代/域名）时，设 CAPNET_PUBLIC_URL=https://capnet.example.com
```

MCP 地址是 `http://<服务器>:8765/mcp`（Streamable HTTP 传输）。

| 客户端 | 怎么填 |
|---|---|
| Claude Code | `claude mcp add --transport http capnet http://<服务器>:8765/mcp` |
| Cursor / Windsurf / Gemini CLI / VS Code / Cline | `python demo.py config <客户端> --url http://<服务器>:8765/mcp --write` |
| Claude.ai / Claude Desktop | 设置 → 连接器 → 添加自定义连接器，填上面的 URL（需要公网 HTTPS 地址） |
| Dify / Coze 等平台 | 在"MCP 服务"或"工具"里添加 MCP Server，填 URL |

同一个端口同时也是 hub（接收上传的轨迹），所以远程用户的上传会直接进入这台服务的评分和归纳。

### 1.4 方式 C：REST / OpenAPI（不支持 MCP 的平台）

服务起来以后：

- `GET /openapi.json`：OpenAPI 3.1 描述。可以直接导入 **GPTs 的 Actions**、Coze/Dify 的"自定义插件 / 从 OpenAPI 导入"、n8n 的 HTTP 工具。描述里已经带上了使用规范。
- `POST /v1/tools/<工具名>`：请求体是参数 JSON，返回 `{"text": ..., "is_error": ...}`。
- `GET /v1/tools`：工具清单；`GET /v1/rules`：使用规范（Markdown）。

```bash
curl -X POST http://<服务器>:8765/v1/tools/plan_task \
  -H "Content-Type: application/json; charset=utf-8" \
  --data-binary @- <<'EOF'
{"query": "抖音视频完播率低，怎么改", "market": "cn"}
EOF
```

请求体必须是 UTF-8 编码。Windows 的 Git Bash 里直接用 `-d '中文'` 可能编码不对，请用文件或 `--data-binary`。

### 1.5 方式 D：Function calling / Python 库

```bash
python demo.py tools --format openai      # 也可以是 anthropic / gemini / mcp
```

把导出的工具定义交给模型；模型发起调用时，用本地库 `Server().call(name, args)` 或远程 `POST /v1/tools/<name>` 执行，再把结果回给模型。完整示例见 `examples/function_calling.py`，里面有 OpenAI 风格循环的写法。

### 1.6 把使用规范交给 agent（所有方式都要做）

规范只有一份：`capnet/agent_rules.md`，用 `python demo.py rules` 打印。

| 客户端 | 放哪里 |
|---|---|
| Claude Code | 复制 skill：`cp -r <CAPNET>/.claude/skills/capnet ~/.claude/skills/`（PowerShell 用 `Copy-Item -Recurse`） |
| Codex CLI | `python demo.py rules >> AGENTS.md`（项目里），或追加到 `~/.codex/AGENTS.md` |
| Gemini CLI | `python demo.py rules >> GEMINI.md`，或追加到 `~/.gemini/GEMINI.md` |
| Cursor | 存为项目的 `.cursor/rules/capnet.mdc` |
| Windsurf / Cline / Copilot | 分别存为 `.windsurf/rules/capnet.md`、`.clinerules`、`.github/copilot-instructions.md` |
| GPTs / Coze / Dify / 自研 | 粘进系统提示（Instructions） |
| 支持 MCP prompt 的客户端 | 也可以直接选用 capnet 提供的 prompt `capnet_rules` |

就算不放，MCP 握手时下发的简要说明和工具描述里也写了关键规则（人工工具不能假装调用；上传必须先展示预览并征得同意）。不过并不是每个客户端都会把握手说明交给模型，所以还是建议放。

### 1.7（可选）私有词表

新建 `~/.capnet/private_terms.txt`，每行写一个不想外传的词，比如公司名、产品名、客户名、同事姓名。汇总轨迹时，这些词会被替换成 `[私有]`。Windows 上 `~` 指 `C:\Users\<你>\`。

远程模式下用不了本机的词表，agent 可以在调用 `summarize_trace` 时传 `private_terms: ["ACME", ...]`。这些词只用于这一次清理，不会保存。

## 2. 试一下

在**任意项目、任意已接入的 agent** 里直接提需求：

> 我们的护肤品抖音视频播放量一直上不去，帮我出一个完整的视频改进计划

agent 应该会：

1. 调用 `plan_task`，返回"营销视频诊断与改进"工作流。工作流共 7 个阶段，每个阶段写明目标、方法、交付物和验收指标，并为每个工具位推荐工具（按国内/海外市场区分）。
2. 先向你要计划里"开工前需要你提供"的材料，比如后台数据、视频文件。
3. 按阶段推进：标着"agent 可调用"的工具可以直接用；标着"人工使用"的工具（剪映、巨量引擎后台这类 GUI 工具）只会推荐给你，由你自己操作。

其他可以试的问题：

| 领域 | 示例提问 |
|---|---|
| 电商 | 新品保温杯要上淘宝，帮我规划主图视频和详情页短视频 |
| 账号增长 | 想做一个讲职场的个人 IP 账号，从 0 起号怎么做 |
| 品牌 | 新茶饮品牌秋季上新，做一波全网传播 |
| 课程 | 把我的 Excel 培训讲义做成一套 10 节的网课视频 |
| 播客 | 做一期 40 分钟的科技访谈播客，从选题到发布 |
| 直播 | 昨晚直播 GMV 掉了一半，帮我复盘 |
| 短剧 / 游戏 / 解说 | 做一集 2 分钟的 AI 短剧 / 做一个网页小游戏 / 把这部电影做成解说视频 |
| 不该走工作流的 | 播客耳机推荐哪款？（应直接回答，不出计划） |

也可以点名调用：

- "用 capnet 查一下有什么能自动转字幕的工具"，对应 `find_capability`。
- "列出 capnet 的所有工作流"，对应 `list_workflows`。

### 6 个 MCP 工具一览

| 工具 | 作用 |
|---|---|
| `plan_task(query, task_type?, market?)` | 任务 → 工作流 → 逐阶段方法 + 工具推荐。`task_type`：produce / improve / grow / launch / review / qa；`market`：cn / global |
| `find_capability(query, domain?, k?, market?)` | 只缺一个能力时，查合适的工具 |
| `list_workflows(industry?)` / `get_workflow(workflow_id)` | 浏览工作流库 |
| `summarize_trace(...)` | 把执行记录整理成清理后的预览，**不上传** |
| `submit_trace(preview_id, consent)` | 用户确认后上传；`consent=false` 会删除本地预览 |

## 3. 能力社区：flow 怎么长出来、怎么被评价

capnet 分两层：

| 层 | 是什么 | 谁维护 | 能被社区改动吗 |
|---|---|---|---|
| 🏛 **基石层** | 能力卡（`data/*.json`）+ 评审过的 flow（`data/workflows/`） | 系统维护者 | 不能。社区反馈只给它打分、提示"哪一步常被跳过"，供维护者改进 |
| 🌱 / ✅ **社区层** | 用户在使用中走出来的 flow | 自动归纳 | 自动上架、升级、下架 |

**它是怎么长的**：每次任务结束，agent 会调用 `finish_task`，记录这次对话里观察到的情况。你什么都不用做：

- **结果**：你采用了 / 只用了一部分 / 放弃了；
- **纠正次数**：你说了几次"不对""重来"；
- **跳过的阶段**：计划里有哪几步没做；
- **实际步骤**：用了哪些工具（也就是你在推荐里选了哪个）、返工了几次、每一步的方法。

这条反馈同时用在三处：

1. **工具评分**：选用、成功、返工都会计入工具排名。
2. **flow 评分**：接受率高、纠正少的 flow 排得更靠前；某一步被多数人跳过时，计划里会提示。
3. **注册新 flow**：没有现成 flow 时，你和 agent 走出来的这条路会成为 🌱 社区 flow；
   3 位以上独立用户走通同一条路，就升级为 ✅ 已验证；接受率掉到 60% 以下会自动下架。

计划里会显示每条 flow 的来源与口碑，例如：

> **来源与口碑** 🌱 社区流程 · 新（走过的人还少，属于探索性推荐） · 2 人走通 · 接受率 100%

### 上报方式：开始前选定

**收集是隐式的，上报方式由你事先决定**。安装时（或第一次用时）agent 会问你一次：

| 选项 | 含义 |
|---|---|
| `auto` 自动上报 | 每次自动上报清理后的思路，不再逐次询问 |
| `ask` 每次先确认 | 每次先把预览给你看，你同意才上报 |
| `off` 不上报 | 只在本机生效：本机的评分和"你上次这样做过"照常可用，什么都不会离开你的电脑 |

随时可以改：`capnet share auto|ask|off`，或者直接让 agent 改。不上报不影响任何路由结果。

### 会上报什么

**会上报的**：问题类型（例如"营销视频播放量低"）、每一步的领域、工具 id、是否成功、返工次数、一句话方法、可迁移的经验，以及上面的隐式反馈（结果、纠正次数、跳过的阶段）。

**不会上报的**：

- 任务原文、产出内容、成本、精确时间（只精确到天）；
- 注册表之外的工具名；
- 密钥、邮箱、电话、证件号、卡号、IP、文件路径、链接、@账号、金额、《作品名》、"张总 / 李经理"这类称谓，以及你私有词表里的词。

清理在记录之前完成，所以本机保存的也是清理后的版本。你的身份只表现为一个哈希：本地模式下是本机随机安装 id 的哈希；远程模式下是请求头 `X-Capnet-Client` 或 MCP 会话 id 的哈希。

> ⚠ 规则无法识别任意人名和公司名。选 `ask` 时请认真看一眼预览；无论选哪种，都建议把敏感专名写进私有词表 `~/.capnet/private_terms.txt`。

### 社区 hub：让大家的 flow 汇到一起

| 情况 | 去向 |
|---|---|
| 没设 `CAPNET_HUB_URL` | 只写入本机 hub（`~/.capnet/hub/`，仓库模式为 `data/hub/`） |
| 设了 `CAPNET_HUB_URL=http://某地址:8765` | 按上报方式上报到那台 hub；同时定期从它拉取社区 flow 与评分（`capnet sync` 可手动拉取） |

起一个社区 hub（同时提供远程 MCP / REST）：

```bash
capnet serve --host 0.0.0.0 --port 8765
```

接入者二选一：直接用远程 MCP（见 1.3）；或者本地安装，再加上环境变量：

```bash
capnet setup --env CAPNET_HUB_URL=http://<hub 地址>:8765 --share ask
```

用远程 MCP 时，服务端收到即算上报，所以 agent 会在每次 `finish_task` 里带上你选的上报方式；你选 `off` 时，服务端什么都不存。

hub 收到反馈后，会在服务端再清理一遍、去重，然后立刻计入工具排名、flow 评分，并重新归纳社区 flow。

## 4. 维护者：守住基石层

```bash
capnet flows                             # 所有 flow 的层级、信任分、使用次数、接受率、平均纠正、常被跳过的阶段
python demo.py hub stats                 # 收到多少轨迹、多少贡献者
python demo.py hub refresh               # 按更严的门槛（≥3 位独立贡献者、成功率 ≥ 0.6）归纳草稿到 data/workflows_drafts/
python demo.py promote <workflow_id>     # 评审通过，把社区 flow 升为基石 flow（移入 data/workflows/）
python demo.py gaps                      # 大家问了、但注册表答不上来的能力缺口
python demo.py eval --file data/eval/blind.json   # 改了工作流或打分后跑回归评测
```

建议的节奏：定期看 `capnet flows`。基石 flow 接受率偏低或某一步常被跳过，就修改它；社区 flow 已验证且稳定，就评审后升为基石。

### 自己加一个工作流

参照 `data/workflows/marketing-video-improve.json` 写一个 JSON，放进 `data/workflows/`：

- 每个阶段：`goal / method / deliverable / checks`；
- 每个工具位：`slot_id / domain`，可选 `alt_domains`；
- `intents`：用户会怎么描述这类任务。

写完后用 `python demo.py plan "<你的典型提问>"` 看能不能命中。

### 自己加工具卡

往 `data/catalog/*.json` 里加卡片，字段参照 `business.json`。

- `markets`：写 `["cn"]`、`["global"]`，或两者都写。
- `accessibility`：`api` / `cli` / `mcp` 表示 agent 可调用，`gui` / `manual` 表示人工使用。
- `access`：**必须写接入渠道**。
  - API 工具：写 `api.auth` 鉴权方式、`api.key_url` 凭证申请页、`api.env` 环境变量、`api.docs` 文档。
  - 软件：写 `download` 或 `web`。
  - 人工服务：写 `hire` 找人渠道。

`tests/test_access.py` 会检查每个工具的接入渠道，缺了测试不过。

## 5. 环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `CAPNET_HOME` | `~/.capnet` | 安装 id、私有词表、待确认预览（`pending/`） |
| `CAPNET_PRIVATE_TERMS` | `~/.capnet/private_terms.txt` | 私有词表路径 |
| `CAPNET_HUB_URL` | 空 | 远端 hub 地址，空表示写本机 |
| `CAPNET_HUB_DIR` | `<CAPNET>/data/hub` | 本机 hub 数据目录 |
| `CAPNET_DRAFTS_DIR` | `<CAPNET>/data/workflows_drafts` | 归纳出的工作流草稿目录 |
| `CAPNET_API_KEY` | 空 | `serve` 的访问口令；设了以后除 `/v1/health` 外都要 `Authorization: Bearer` |
| `CAPNET_PUBLIC_URL` | 按请求 Host | 写进 OpenAPI `servers` 的对外地址 |

## 6. 常见问题

- **客户端显示连接失败**：先在终端单独跑 `python <CAPNET>/demo.py mcp`，确认不报错（它会安静地等待输入，用 Ctrl+C 退出）。另外确认 Python 版本是 3.11 及以上。远程模式下先打开 `http://<服务器>:8765/v1/health` 看服务是否在线。
- **agent 不调用 capnet**：确认按 1.6 把使用规范放进了该客户端的规则文件或系统提示；或者在提问里直接说"用 capnet"。
- **英文提问匹配不上**：当前检索只支持中文，这是已知限制。
- **问题没命中任何工作流**：agent 会按常识自行拆解；这次查询会记进缺口日志，可以用 `python demo.py gaps` 查看。
